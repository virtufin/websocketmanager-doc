Virtufin WebSocket Manager

A WebSocket management service with REST and gRPC APIs, built on ASP.NET Core with Dapr integration.

Features

  • WebSocket connection management
  • REST API for WebSocket operations
  • gRPC API for WebSocket operations
  • Dapr integration for pub/sub and state management
  • Health checks and monitoring

Getting Started

Prerequisites

  • .NET 8.0 SDK or later
  • Dapr CLI (for local development)
  • Docker (for containerized deployment)

Building and Running

  1. Clone the repository

    git clone <repository-url>
    cd virtufin-websockets

  2. Build the project

    dotnet build

  3. Run the application

    Default ports (HTTP on 5001, gRPC on 5002):

    dotnet run --project src/Virtufin.WebSocketManager

    Custom HTTP port:

    dotnet run --project src/Virtufin.WebSocketManager -- --http-port 8080

    Custom gRPC port:

    dotnet run --project src/Virtufin.WebSocketManager -- --grpc-port 8081

    Both custom ports:

    dotnet run --project src/Virtufin.WebSocketManager -- --http-port 8080 --grpc-port 8081

Port Configuration

The application supports separate ports for HTTP/REST APIs and gRPC services:

Command-Line Arguments

  • --http-port, -h: HTTP port for REST APIs (default: 5001)
  • --grpc-port, -g: gRPC port for gRPC services (default: 5002)

Environment Variables

  • HttpPort: Same as --http-port (e.g., HttpPort=8080)
  • GrpcPort: Same as --grpc-port (e.g., GrpcPort=8081)

Configuration Precedence

  1. Command-line arguments (highest priority)
  2. Environment variables
  3. Default values (5001 for HTTP, 5002 for gRPC)

Protocol Configuration

  • HTTP Port (REST APIs): Supports HTTP/1.1 and HTTP/2 protocols
  • gRPC Port: Supports HTTP/2 with plaintext (no TLS required)

Port Validation

  • Ports must be between 1 and 65,535
  • HTTP and gRPC ports must be different
  • Invalid configurations will display an error and exit

Example Usage

# Start with default ports
dotnet run --project src/Virtufin.WebSocketManager

# Start with custom ports
dotnet run --project src/Virtufin.WebSocketManager -- --http-port 3000 --grpc-port 3001

# Using environment variables
export HttpPort=4000
export GrpcPort=4001
dotnet run --project src/Virtufin.WebSocketManager

Migration from Single Port

If you were previously using the single --port argument:

  1. Before: --port 5001
  2. After: Use --http-port 5001 --grpc-port 5002 or just --http-port 5001 (gRPC defaults to 5002)

API Endpoints

HTTP/REST API (on HTTP port)

  • GET /websockets - List all WebSocket connections
  • POST /websockets/{connectionId}/connect - Connect a WebSocket
  • POST /websockets/{connectionId}/disconnect - Disconnect a WebSocket
  • POST /websockets/{connectionId}/messages - Send a message
  • GET /health - Health check endpoint
  • Swagger UI available at /swagger

gRPC API (on gRPC port)

  • WebSocketManagerService - gRPC service for WebSocket operations
  • gRPC reflection enabled for client discovery
  • gRPC health checks available

Python Client

A reusable Python client is available for interacting with the gRPC service:

import sys
from pathlib import Path
sys.path.insert(0, '/path/to/project/src/python')
from virtufin import WebSocketManagerClient, SyncWebSocketManagerClient

# Async usage (default: localhost:5002)
async with WebSocketManagerClient() as client:
    connection_id = await client.connect_websocket("wss://example.com")
    await client.send_message(connection_id, {"type": "ping"})
    connections = await client.list_connections()

# Or with explicit host and port:
async with WebSocketManagerClient("localhost", 5002) as client:
    connection_id = await client.connect_websocket("wss://example.com")
    await client.send_message(connection_id, {"type": "ping"})
    connections = await client.list_connections()

# Sync usage
with SyncWebSocketManagerClient("localhost", 5002) as client:
    connection_id = client.connect_websocket("wss://example.com")
    client.send_message(connection_id, {"type": "ping"})
    connections = client.list_connections()

The client features:

  • Auto-reconnection and connection management
  • gRPC reflection for service discovery
  • Both async and sync interfaces
  • Comprehensive error handling
  • Context manager support

See the Python examples for more details.

Development

Testing

Run tests with:

dotnet test

Logging

Control log level with --log-level argument:

dotnet run --project src/Virtufin.WebSocketManager -- --log-level Debug

Available log levels: Trace, Debug, Information, Warning, Error, Critical, None

Troubleshooting

Port Already in Use

If you get an error that a port is already in use:

  • Check for other applications using the same port
  • Use a different port with --http-port and/or --grpc-port

gRPC Connection Issues

  • Ensure you're connecting to the correct gRPC port (default: 5002)
  • Use plaintext HTTP/2 connection (no TLS required)
  • Verify the gRPC client is configured for HTTP/2 plaintext
